# API Documentation

## Purpose

API documentation enables developers to understand, integrate, and maintain APIs efficiently.

Documentation should be generated from the contract whenever possible.

---

# Documentation Requirements

Every published API should include:

- Overview
- Authentication
- Base URL
- Version
- Endpoints
- Request examples
- Response examples
- Error codes
- Rate limits
- Pagination
- Changelog

---

# Endpoint Documentation

Every endpoint should document:

- Purpose
- Parameters
- Request body
- Response body
- Status codes
- Authorization
- Examples

---

# Examples

Every API should include realistic examples for:

- Successful requests
- Validation failures
- Authorization failures
- Resource not found
- Internal server errors

---

# SDK Documentation

Generated SDKs should contain:

- Installation
- Configuration
- Authentication
- Sample requests
- Error handling

---

# Changelog

Every API release should include:

- New features
- Deprecated fields
- Breaking changes
- Migration guidance
